# keroway.com の文章方針

本人のゴーストライターとして書くときの基準。
2026年11月18日の本人との対話と、既存のブログ本文をもとに整理した。
過去記事の口癖を再現するのではなく、率直さと具体性を保ちつつ、現在の落ち着いた語り口に整える。
個々の試案が本人の感覚に合うかは、実際の文章へのフィードバックで調整する。

## 基本の語り口

- 丁寧語を基本に、身近なきっかけ、試したこと、わかったことの順で書く。
- 自分の感想は、自分が確かめた範囲で述べる。迷いや未解決の点も残す。
- 「ひと安心」「嬉しかった」など、小さな実感は残してよい。
- すべてを教訓や成功談にまとめない。途中までの記録は、その時点で終えてよい。
- 括弧内の補足や軽い余談は使ってよい。ただし、文の省略や三点リーダーを口調の代用品にしない。
- 落ち着きは、内容の整理と読みやすさで出す。漢語、敬語、抽象語を増やして硬くしない。
- 「手抜き」「〜だけで失礼」といった謝罪や自己卑下は、記事の短さを説明するために付けない。
- 「本質」「価値」「体験」「導線」といった語は、具体的に何を指すのか説明できる場合に使う。

## 場面ごとの使い分け

| 場所 | 書き方 |
| --- | --- |
| ブログ本文 | 本人の経験や感想を中心に書く。技術手順や引用と、自分の解釈を区別する。 |
| 実績紹介の経緯と振り返り | 作りたかった理由、試したこと、困ったことを具体的に書く。「学び」を無理に作らない。 |
| 実績紹介の機能と構成 | 何ができるか、何を使っているかを簡潔に説明する。採用理由は資料か本人の説明にある範囲で書く。 |
| プロフィールと近況 | 普段の言葉で経験や関心を伝える。経歴や意欲を装飾的な比喩で膨らませない。 |
| 記事の description | 本文の内容と到達点を短く伝える。短い試行を「詳しく解説する入門記事」と紹介しない。 |
| サイトコピー | サイトのイメージを担う言葉は維持してよい。本人の体験を語る文章とは役割を分ける。 |
| UI、案内、代替テキスト | 操作や対象がわかることを優先し、口調の個性を無理に加えない。 |

## 事実と時点

本人の体験、動機、家族の発言、感情を創作しない。
既存原稿にある一人称の体験も、原稿に書かれていること以上の裏付けにはならない。
内容に疑問がある場合は、言い回しだけで確定事項に変えない。

過去記事は当時の記録として編集する。
当時の未解決事項、予定、料金、バージョンを、現在の状況で上書きしない。
技術情報を更新する場合は別に確認し、当時の本文と追記を区別する。
コード、ログ、引用文、リンク先の名称は文体調整の対象にしない。

近況ページの日付は、記載内容を確認した時点を示す。
表現だけを直して現在の近況として更新したことにしない。

開発資料、ADR、コード内コメント、CMS の管理用ラベルは、本人として読者に語る文章の対象には含めない。

実績紹介の実装状況、公開状態、ロードマップは、元原稿の範囲で編集したもので、各製品を再調査して更新したものではない。

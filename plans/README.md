## Findings considered and rejected

- `BaseHead.astro` JSON-LD uses `set:html`, but the payload is produced with `JSON.stringify(...)` from structured objects, so it was not treated as an actionable XSS finding.
- `/api/trigger-build` bearer-token comparison itself was not treated as a vulnerability: the route has a production fail-fast when `CRON_SECRET` is missing and returns before reading the deploy hook on wrong tokens. The actionable gap is CI coverage, captured in Plan 004.
- Pagefind search was not reported as untested because `tests/playwright/blog-search.spec.ts` and `tests/playwright/pagefind-index.spec.ts` already cover search UI and build artifact generation.
- A full documentation sync from Astro 6 to Astro 7 was previously deferred; it is now covered by Plan 006.
- Local `.env` contains legacy Keystatic environment variable names. Because this repository is public and `.env` may contain sensitive local values, do not publish those locations in a public GitHub issue without explicit user confirmation. Plan 006 cleans `.env.example`; local `.env` cleanup/rotation should be handled privately if those values are real credentials.

## Plan 013 implementation notes (2026-08-11)

- `public/admin/config.yml` の `canonicalUrl` / `lpUrl` / `repoUrl` / `demoUrl` に
  issue #652 の提案どおり `pattern: ['^https?://\S+$', 'http(s):// で始まる URL を
  入力してください']` を追加。`lpUrl` は required のため元の正規表現のままにした。
- **issue の提案から1点変更**: `canonicalUrl` / `repoUrl` / `demoUrl`（すべて
  `required: false`）に issue 提案の正規表現をそのまま使うと、**値が空でも**
  pattern 不一致でエラーが出てしまうことを `?test-repo` バックエンドでの目視確認
  （受け入れ条件）で発見した。正規表現を `^$|^https?://\S+$`（空文字列も許容）に
  修正して解消した。`lpUrl` は required なので空文字列を許容する必要がなく、
  元の正規表現のまま。
- **PR #660 の自動レビューで追加発見**: `pattern` は入力時の UI バリデーションのみで、
  Sveltia CMS は `required: false` な未入力フィールドを既定で `""`（空文字列）として
  frontmatter に書き出す（`?test-repo` バックエンドで OPFS 上の保存済みファイルを直接
  読んで実測確認済み: `repoUrl: ""` / `demoUrl: ""` / `updatedAt: ""` が実際に書かれていた）。
  `content.config.ts` は `.optional()`（`undefined` のみ許容）なので、`z.url()` はもちろん
  `z.coerce.date()` も空文字列を弾き、CMS 上は保存できてもビルド時に初めて失敗する
  late failure になっていた（issue #652 が解消しようとした問題そのもの）。
  `config.yml` ルートに `output: { omit_empty_optional_fields: true }` を追加し、
  未入力の optional フィールドをキーごと省略させて解消した（Sveltia CMS 公式ドキュメント
  `configuration.md` に記載の標準対処。URL フィールドに限らず全 optional フィールドに
  効くグローバル設定のため、`updatedAt` 等 URL 以外の late failure も併せて解消される）。
  修正後、同じ `?test-repo` バックエンドで OPFS 上の保存結果を再確認し、
  未入力フィールドがキーごと省略されることを実測確認済み。
- `pnpm run test:admin` で新規 CMS admin 系リグレッションが無いことを確認済み。

## Plan 014 implementation notes (2026-08-11)

- happy-dom（jsdom より軽量）を devDependencies に追加し、`vitest.config.ts` の `include` に
  `src/scripts/**/*.test.ts` を追加。各テストファイル先頭の `@vitest-environment happy-dom`
  docblock で個別に環境を切り替え、`src/lib/**` の既存 node 環境テストには影響しない。
- **既知の相性問題**: `test:unit` が実際に動く環境（ローカル/CI とも `mise.toml` / CI の
  `actions/setup-node` で Node 26 系にピン、CLAUDE.md 「C5」参照。Vercel の 24 系フォールバックは
  デプロイ時のみでテスト実行には無関係）では Web Storage API が既定で有効になっており、グローバル
  `localStorage` に `--localstorage-file` を渡さずアクセスすると例外になる。この挙動は Node
  バージョンで変遷している（v22〜24 は `--experimental-webstorage` フラグ依存、v25 で既定有効化、
  v26 で未指定時に例外へ変更）ため「Node 22+」と一括りにしないこと。これが vitest の happy-dom
  環境が `globalThis` へ happy-dom 版 `localStorage` をインストールする処理と衝突し、
  `localStorage` / `window.localStorage` が `undefined` になる。`package.json` の
  `test:unit` / `test:unit:watch` に `NODE_OPTIONS=--no-experimental-webstorage` を付けて
  回避した（CI もこのスクリプト経由のため同じ回避策が効く）。
- **既知の相性問題その2**: happy-dom の `Storage` は内部で `Proxy` 経由にメソッドをバインド・
  キャッシュするため、`vi.spyOn(Storage.prototype, "getItem")` は最初のアクセス以降効かない。
  `localStorage` グローバル自体を `vi.stubGlobal` で丸ごと差し替える方式に変更した。
- `setReduceMotion()` は末尾で常に `applyMotionPreferences()` を呼んで再同期するため、
  `localStorage.setItem` が失敗した直後は「反映されなかった」状態に戻る。**OS が
  `prefers-reduced-motion: reduce` を返さない前提では** `reduce-motion` クラスが外れる
  （テストも matchMedia を `matches: false` にモックした状態でこれを検証している）。
  OS が reduce を要求している場合は `applyMotionPreferences()` の再同期後も
  `reduce-motion` クラスは残るため、「必ず外れる」わけではない点に注意
  （`font-size` / `text-spacing` / `underline-links` の `set*` は再同期を呼ばないため、
  setItem 失敗時もトグルした class がそのまま残る — reduce-motion とは挙動が異なる）。
